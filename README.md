# Dubizzle Automotive Assistant

A conversational car-search assistant that helps users explore vehicle listings, refine searches using natural language, ask follow-up questions, arrange viewings, and qualify potential leads.

## Features

* **Hybrid retrieval:** Applies structured filters and semantic ranking to find relevant car listings.
* **Natural-language search:** Uses Gemini to extract search constraints from user messages.
* **Context-aware follow-ups:** Retains search filters and previously retrieved listings within a conversation.
* **Vehicle details:** Supports questions about selling price, monthly payments, mileage, manufacturing year, trim, and descriptions.
* **Booking assistance:** Handles conversations for arranging vehicle viewings.
* **Lead qualification:** Collects information needed to qualify prospective customers.
* **REST API:** Exposes endpoints for health checks, car searches, individual listing retrieval, and conversational requests.
* **Embedding cache:** Saves listing embeddings and validates cached data against the dataset and model configuration.

## Architecture

The application separates the user interface, API, conversation orchestration, retrieval, and business workflows.

* **Streamlit:** Provides the conversational interface and displays vehicle listings.
* **FastAPI:** Exposes the application through REST endpoints.
* **Chat service:** Coordinates filter extraction, retrieval, response generation, follow-ups, booking, and lead qualification.
* **Gemini:** Interprets natural-language search requests and generates responses grounded in retrieved listings.
* **Hybrid retrieval:** Applies structured constraints before ranking eligible listings using embedding similarity.
* **Conversation memory:** Maintains recent messages, search filters, and previous listings in memory.

## Retrieval and Design Decisions

Structured filters are applied before semantic ranking so constraints such as selling price, monthly payment, mileage, manufacturing year, make, and model can restrict the eligible listings. The remaining candidates are ranked using normalized embeddings generated by `sentence-transformers/all-MiniLM-L6-v2`. Selling price and monthly payment are represented separately to avoid confusing a vehicle's advertised price with its financing terms.

Listing embeddings are cached locally. The application checks the embedding model, dataset fingerprint, and listing IDs before reusing a cache; otherwise, it regenerates the embeddings. Conversation state is managed separately from retrieval, allowing follow-up messages to retain existing filters, update constraints, or start a new search.

Gemini service failures are handled with user-friendly error messages rather than exposing raw service errors. However, natural-language filter extraction and response generation still depend on Gemini being available.

## Setup

### Prerequisites

* Python 3.13 or later
* [uv](https://docs.astral.sh/uv/)
* A Gemini API key

### 1. Clone the repository

```bash
git clone https://github.com/Shreiya-Muthuvelan/dubizzle-car-assistant.git
cd dubizzle-car-assistant
```

### 2. Install dependencies

```bash
uv sync --locked
```

### 3. Configure the API key

Create a `.env` file in the project root:

```dotenv
GOOGLE_API_KEY=your_gemini_api_key_here
```

Obtain your key from [Google AI Studio](https://aistudio.google.com/).

Never commit your `.env` file or expose your API key in the repository.

### 4. Start the backend

```bash
uv run uvicorn main:app --reload
```

The API will be available at `http://127.0.0.1:8000`.

Interactive API documentation is available at `http://127.0.0.1:8000/docs`.

### 5. Start the Streamlit interface

Open a second terminal in the project directory and run:

```bash
uv run streamlit run streamlit_app.py
```

The Streamlit interface communicates with the FastAPI backend running at `http://127.0.0.1:8000`.

On the first run, the application may need to download the embedding model and generate listing embeddings.

## API Endpoints

| Endpoint                 | Description                                           |
| ------------------------ | ----------------------------------------------------- |
| `GET /health`            | Checks backend availability.                          |
| `GET /cars`              | Searches listings using filters and semantic ranking. |
| `GET /cars/{listing_id}` | Retrieves a specific listing.                         |
| `POST /chat`             | Processes a conversational request.                   |

## Limitations and Future Improvements

Conversation memory is currently stored in an in-memory dictionary, so it does not survive a backend restart or provide persistent recall across separate conversations. Persistent storage linked to a user identity could support cross-session preference recall.

Other potential improvements include broader automated tests, retrieval-quality evaluation, more robust natural-language fallback behaviour when Gemini is unavailable, and persistent storage for bookings and leads.
